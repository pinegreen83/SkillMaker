# SkillMaker

Unreal Engine 5.8 C++ 프로젝트입니다. 무기·애니메이션·발사체 목록을 조회하는 제작 UI, 스킬 데이터 편집·SaveGame 저장 코드, 캐릭터의 몽타주·발사체 실행 코드, 훈련장의 저장 스킬 선택·슬롯 배치·매핑 현황 UI가 있습니다.

현재 코드는 `SkillMaker` 런타임 모듈 하나로 구성됩니다. 소스의 `UEEditor`와 문서의 제작 편집기는 게임 맵에서 HUD·UMG로 생성하는 화면을 가리킵니다. 별도 Unreal Editor 확장 모듈은 없습니다.

이 프로젝트는 같은 직업의 플레이어가 동일한 스킬을 사용하는 것이 당연하게 여겨지는 구조에 대한 의문에서 시작했습니다. 직업이 가능한 행동을 직접 금지하는 대신, 세계의 일관된 성질과 제약 안에서 플레이어가 자신의 능력과 전투 방식을 만들 수 있는지를 실험합니다. 자세한 배경은 [프로젝트의 출발점과 세계관 방향](Docs/PROJECT_VISION.md)에 정리했습니다.

문서의 기본 언어는 한국어이며, 코드·명령어·식별자·경로는 원문을 유지합니다.

## 코드에서 확인한 주요 흐름

- 리소스 조회: 선택 위젯 → `USKDataManagerSubsystem` → 무기·애니메이션·발사체 데이터 테이블.
- 저장: 제작 메인 위젯의 저장 요청 → HUD의 `CurrentEditingSkill` → `USKSaveGameSubsystem` → `USKPlayerSkillSave` → 저장 슬롯.
- 프리뷰: 상세 위젯 → 제작 HUD → 프리뷰 캐릭터 → `USKSkillComponent` → 몽타주 → 이름이 일치하는 노티파이 → 발사체 생성.
- 훈련장: 기존 저장 스킬 선택 위젯을 재사용하고, 선택 후 Q/E/R/F 할당 화면으로 전환합니다. C++ 런타임 Enhanced Input에서 Q→슬롯 0, E→슬롯 1, R→슬롯 2, F→슬롯 3 연결을 보장합니다. 숫자 0 입력은 현재 슬롯 매핑 현황을 열고 스킬 선택 화면을 거쳐 배치를 변경합니다. 제작·훈련장 맵 왕복, 새 저장 스킬의 목록 반영과 선택 데이터 로드를 확인했습니다.

신규 스킬 생성은 무기 → 애니메이션 → 세부사항 순서로 진행합니다. 기존 스킬 수정도 저장 데이터를 불러온 뒤 같은 순서로 진입하며, 무기·애니메이션·타입·속성·이펙트·트리거의 기존 선택을 표시합니다. 세부사항 화면은 기본·속성·이펙트/사운드·트리거 탭으로 구성되며, 단일 속성 선택과 호환 발사체 필터, 선택 상태 표시, 기본 탭 스크롤을 제공합니다. 몽타주 미리보기와 저장, 선택한 트리거 시점의 발사체 이펙트·사운드 출력과 타겟 충돌까지 실제 UI에서 확인했습니다. 제작·훈련장 맵 왕복, 저장 스킬의 훈련장 목록 반영, Q/E/R/F 슬롯 배치·실행과 숫자 0 매핑 현황·재배치도 확인했으며, 타겟 더미 피해 연결은 [구현 현황](Docs/IMPLEMENTATION_STATUS.md)에 남아 있습니다.

## 검토 범위

2026-09-07 기준 C++·설정 파일의 정적 검토, 에디터 타깃 빌드, `SkillMakingMap` 명령행 로드와 제작 UI 흐름의 사용자 실행 확인을 반영했습니다. `SkillTrainingMap`과 `SkillMakingMap`의 양방향 이동, 제작 직후 저장한 스킬의 훈련장 목록 표시, Q/E/R/F 슬롯 할당과 지정 키 스킬 실행, 숫자 0 매핑 현황 표시와 재배치도 사용자가 확인했습니다. 재시작 후 복원, 패키징, 멀티플레이와 타겟 더미 피해는 아직 검증하지 않았습니다. `Content/` 에셋은 저장소 용량 정책에 따라 Git 추적에서 제외합니다. 프로젝트의 배경과 세계관 방향, 프로토타입 설계와 구현 현황은 각 문서에서 구분해 기록합니다.
