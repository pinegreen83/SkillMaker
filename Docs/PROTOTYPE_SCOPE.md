# 프로토타입 범위

## 문서 목적

이 문서는 SkillMaker의 최초 프로토타입에서 실제로 완성하고 검증할 사용자 흐름을 정의한다. 프로젝트를 시작한 이유와 세계관 방향은 [프로젝트의 출발점과 세계관 방향](PROJECT_VISION.md), 현재 코드 상태와 연결 누락은 [구현 현황](IMPLEMENTATION_STATUS.md)을 참고한다.

프로토타입은 전체 속성 체계와 성장 시스템을 완성하는 단계가 아니다. 제한된 리소스를 조합하여 만든 스킬이 제작 화면의 미리보기와 훈련장의 실제 사용까지 같은 결과로 이어지는지를 먼저 확인한다.

## 프로토타입의 사용자 흐름

프로토타입에서 사용자는 다음 과정을 수행한다.

1. 스킬 제작 화면에서 무기를 선택한다.
2. 선택한 무기에 사용할 애니메이션을 선택한다.
3. 세부사항에서 이번 프로토타입에 사용할 속성을 선택한다.
4. 스킬에서 표현할 이펙트·사운드 묶음을 선택한다.
5. 선택한 애니메이션에서 이펙트·사운드가 발생할 트리거를 선택한다.
6. 완성 중인 스킬을 제작 화면에서 미리 실행해본다.
7. 미리보기 결과를 확인하고 스킬을 저장한다.
8. 훈련장으로 이동하여 저장한 스킬을 불러온다.
9. 저장한 스킬을 실제 입력으로 사용한다.
10. 타겟 더미를 대상으로 스킬의 동작과 결과를 확인한다.

사용자 흐름은 다음과 같이 요약한다.

```text
무기 선택
→ 애니메이션 선택
→ 세부사항 선택
→ 이펙트·사운드 묶음 선택
→ 애니메이션 트리거 선택
→ 제작 화면 미리보기
→ 스킬 저장
→ 훈련장 이동
→ 저장 스킬 불러오기·사용
→ 타겟 더미에서 결과 확인
```

## 프로토타입에서 저장하는 스킬 정보

프로토타입의 저장 데이터는 플레이어가 선택한 스킬 제작법을 나타내야 한다.

- 스킬의 고유 식별자
- 플레이어에게 표시할 스킬 이름
- 선택한 무기 또는 무기 유형
- 선택한 애니메이션
- 세부사항에서 선택한 속성
- 선택한 이펙트·사운드 묶음
- 선택한 애니메이션 트리거
- 훈련장에서 스킬을 다시 구성하고 실행하는 데 필요한 참조 정보

최종 피해량처럼 캐릭터와 장비 성장에 따라 변해야 하는 값을 제작 당시 결과로 고정하는 것은 장기 방향과 맞지 않는다. 다만 프로토타입에서 타겟 더미의 반응을 확인하기 위한 임시 기본값은 사용할 수 있으며, 임시값은 확정된 세계 규칙과 구분해 기록한다.

## 프로토타입 완료 조건

다음 조건을 모두 확인했을 때 최초 프로토타입의 핵심 흐름이 연결된 것으로 본다.

- 무기·애니메이션·이펙트·사운드 목록이 준비된 리소스 데이터에서 표시된다.
- 선택한 무기에 맞는 애니메이션 선택지가 표시된다.
- 세부사항에서 이번 프로토타입에 사용할 속성을 선택할 수 있다.
- 선택한 속성과 호환되는 이펙트·사운드 묶음만 표시된다.
- 선택한 애니메이션에 준비된 유효 트리거가 표시된다.
- 사용자의 선택 결과가 하나의 스킬 제작법으로 유지된다.
- 저장 전에 미리보기를 실행할 수 있다.
- 미리보기에서 선택한 애니메이션과 트리거 시점에 선택한 이펙트와 사운드가 발생한다.
- 스킬에 고유 식별자가 부여되고 SaveGame에 저장된다.
- 저장 후 목록에서 같은 스킬을 다시 조회할 수 있다.
- 훈련장에서 저장한 스킬을 선택하고 플레이어가 사용할 수 있다.
- 훈련장의 실행 결과가 제작 화면의 미리보기와 같은 제작법을 사용한다.
- 타겟 더미가 스킬 명중 또는 효과 적용 결과를 확인할 수 있는 반응을 보인다.
- 필수 리소스나 선택값이 없을 때 저장·미리보기·실행이 잘못 진행되지 않는다.

화면이 존재하거나 개별 함수가 호출되는 것만으로 완료로 보지 않는다. 제작한 하나의 스킬이 저장을 거쳐 훈련장에서 사용되는 전체 흐름을 기준으로 판단한다.

### 현재 달성 상태

2026-09-07 기준 스킬 제작 화면은 신규 생성과 기존 스킬 수정, 기존 선택 복원, 세부사항 탭, 단일 속성 선택, 호환 이펙트·사운드 선택, 트리거 선택, 미리보기와 SaveGame 저장까지 사용자 확인을 마쳤다. 스킬 제작 범위의 1차 프로토타입은 완료된 상태다.

전체 프로토타입은 아직 완료되지 않았다. 다음 핵심 단계는 훈련장에서 저장 스킬을 불러와 입력 슬롯에 연결하고, 제작 미리보기와 같은 실행 경로로 사용하는 것이다.

## 세계관과 장기 설계의 반영 범위

프로토타입에서도 다음 원칙은 이후 확장을 막지 않는 방향으로 반영한다.

- 플레이어는 직접적인 전투 수치보다 준비된 리소스와 의미 있는 선택지를 조합한다.
- 무기, 애니메이션, 이펙트와 트리거는 하나의 고정 에셋으로 합치지 않고 제작법의 구분 가능한 요소로 취급한다.
- 미리보기와 훈련장 실행은 가능한 한 같은 스킬 실행 경로와 저장 데이터를 사용한다.
- 제작한 스킬은 결과 수치만 저장하지 않고 선택한 제작법을 다시 구성할 수 있어야 한다.
- 리소스 추가가 개별 스킬 실행 코드의 반복적인 수정으로 이어지지 않도록 데이터 중심 접근을 유지한다.
- 향후 생성 위치, 전달 형태, 데미지, 상태이상, 무기 궁합과 페널티를 추가할 수 있는 여지를 남긴다.

다음 장기 설계는 프로토타입의 핵심 흐름을 확인하기 전에 모두 구현할 필요가 없다.

- 전체 속성 목록과 계통
- 속성 관여 수준과 플레이어 성장
- 상태이상 축적·확률·저항·감소의 전체 체계
- 스태미너와 마나의 최종 균형
- 제너럴리스트와 스페셜리스트의 성장 구조
- 복합·파생 속성과 속성 간 반응
- 상태이상 재발동 저항과 면역

이 항목을 프로토타입에 일부 임시 적용할 수는 있지만, 정확한 수치와 최종 규칙을 프로토타입 완료 조건으로 삼지는 않는다.

## 확정된 프로토타입 설계

### 세부사항 선택

- 화면과 코드의 개념은 `속성 선택` 하나로 고정하지 않고 `세부사항 선택`으로 둔다. 이후 데미지, 코스트와 추가 제작 요소를 같은 단계에 확장할 수 있어야 한다.
- 이번 프로토타입은 `NonTarget`만 지원한다. 타겟팅 타입 데이터는 확장 가능하게 유지하지만 기존 최소·최대 사거리 UI는 숨기고 관련 필드는 레거시로 보존한다.
- 기본 탭의 스킬 타입은 유지한다. 데미지 데이터와 기존 UI 코드는 저장 호환을 위해 보존하지만 이번 단계의 활성 입력에서는 제외한다.
- 기존 디버프 탭은 속성 탭으로 사용하고 상태이상 데이터와 카드 코드는 향후 확장을 위해 보존한다.
- 세부사항 위젯은 편집 중인 스킬 원본을 별도로 보관하지 않는다. 선택 결과를 델리게이트로 HUD에 전달하고 HUD의 단일 `CurrentEditingSkill`을 갱신한다.

### 속성과 이펙트·사운드 호환성

- 스킬은 `Element` 계층의 Gameplay Tag 하나를 선택한다. 카드 전체를 버튼으로 사용하고 체크 상태와 속성색 배경으로 선택을 표시하며, 다른 속성을 선택하면 이전 선택을 해제한다.
- 이펙트·사운드 묶음은 지원하는 속성을 `FGameplayTagContainer`에 기록하며, 선택한 속성과 호환되는 항목만 목록에 표시한다.
- 기존 발사체 데이터의 지원 속성 목록이 비어 있으면 저장된 리소스가 사라지지 않도록 모든 속성과 호환되는 것으로 취급한다.
- 속성 정의는 사용자 표시명·설명·기준 색상을 가지며 카드 마우스 오버 시 설명을 툴팁으로 표시한다.
- 속성마다 기준 색상을 지정한다. 색상 변경을 지원하는 이펙트는 선택한 속성의 색으로 변경하고, 고유 색상이나 다른 속성 표현을 유지해야 하는 이펙트는 데이터에서 색상 변경을 허용하지 않도록 구분한다. Niagara 사용자 파라미터나 머티리얼 색상 파라미터처럼 에셋이 런타임 색상 입력을 제공하는 경우에만 변경할 수 있으며 임의의 기존 이펙트를 자동으로 재색칠할 수 있다고 가정하지 않는다.

### 무기와 애니메이션 호환성

- 무기 행은 하나의 `WeaponTag`, 애니메이션 행은 여러 `CompatibleWeaponTags`를 가진다.
- `Weapon.Melee` 같은 상위 Gameplay Tag를 애니메이션에 지정하면 그 하위 무기에서 함께 사용할 수 있다.
- 무기와 애니메이션의 호환 태그는 비어 있으면 안 된다. 무기와 속성 호환성은 확장 가능한 계층 질의를 위해 각각 `Weapon`, `Element` 계층의 Gameplay Tag를 사용한다.

### 애니메이션 트리거 선택

- 트리거 선택 단계는 유지한다. 자동 지정으로 단순화할 수 있지만 연속 동작이 하나의 몽타주에 묶인 경우 사용자가 원하는 발동 지점이 다를 수 있다.
- 개발자가 몽타주에 유효한 선택 지점을 준비하고 사용자는 그 범위 안에서 하나를 선택한다.

### 이펙트와 전달 형태의 최초 범위

최초 프로토타입에서 이펙트의 실행 형태는 발사체로 한정한다. 사용자가 선택한 이펙트·사운드 묶음은 애니메이션의 선택된 트리거 시점에 발사체 형태로 생성되고 재생된다.

근접 타격, 자기중심 범위, 지면 지정과 같은 다른 전달 형태는 최초 사용자 흐름을 완성한 뒤 필요한 파트를 순차적으로 추가하는 방식으로 확장한다. 최초 구현을 발사체로 한정하는 것은 장기 설계에서 다른 전달 형태를 배제한다는 의미가 아니며, 이후 실행 형태를 추가할 수 있도록 제작법에서 이펙트와 트리거를 구분하여 유지한다.

현재 코드에서는 선택 리소스와 실행 주체가 `ProjectileActor` 계열에 함께 묶일 수 있다. 최초 프로토타입에서는 이 구조를 사용해 전체 흐름을 먼저 검증할 수 있지만, 문서에서 말하는 이펙트의 장기 개념은 시각 표현 하나에 한정되지 않는다. 이후 전달 형태를 확장할 때 표현 리소스, 충돌 방식과 전달 동작을 분리할 필요가 있는지는 별도 설계에서 결정한다.

### 리소스 로드와 목록 규모

- 데이터 행과 저장 스킬은 몽타주·썸네일·발사체 같은 대형 리소스를 소프트 참조로 보관한다.
- 실행 순간의 일괄 동기 로드는 끊김을 만들 수 있으므로, 실제 데이터 양이 늘어나면 스킬을 불러오는 단계에서 필요한 리소스를 선행 로드하고 재사용하는 정책을 검토한다. 현재 코드의 정확한 로드 지점은 [코드베이스 상세 참조](CODE_REFERENCE.md)의 기준선을 따른다.
- 현재 리소스 수에서는 기존 스크롤 목록을 유지한다. 데이터가 늘어나면 페이징, 리스트 가상화 또는 지연 로드를 검토한다.
- 패키징 검증에서는 데이터 테이블 자체와 테이블이 가진 소프트 참조 에셋이 모두 쿠킹 대상에 포함되는지 확인한다.

## 다음 단계에서 결정할 프로토타입 설계

다음 항목은 사용자 흐름을 구현하기 전에 하나씩 결정한다.

1. 애니메이션만 확인하는 부분 미리보기와 필수 선택을 마친 완성 스킬 미리보기를 어떻게 구분하고 안내할지
2. 저장한 스킬을 훈련장에서 불러오고 슬롯에 장착하는 흐름
3. 제작 화면과 훈련장 사이를 이동하는 방법
4. 타겟 더미가 보여줄 최소 반응과 피해 결과 정보
5. 저장 후 프로세스를 다시 실행했을 때 복원을 완료 조건에 포함할지 여부
6. 최초 프로토타입에서 멀티플레이의 기술적 실행·복제까지 검증할지 여부. PvP 규칙과 상대 스킬 예측 문제는 별도 범위로 둔다.
7. 훈련장 리소스와 화면에서 블루프린트가 담당할 배치·표현, C++이 담당할 실행·저장 범위

위 항목은 한 번에 모두 확정하지 않고, 프로토타입의 범위를 크게 바꾸는 내용부터 순서대로 결정한다.
